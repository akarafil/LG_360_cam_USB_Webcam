# lg_cam - Konuşma ve Gelişim Günlüğü

## 2026-08-16
- Proje dizini oluşturuldu, log.md dosyası başlatıldı.
- Hedef belirlendi: LG 360 CAM (LG-R105)'i bilgisayara USB webcam gibi çalıştırmak; her adım GitHub'a düzenli push edilecek.
- USB analizi: kamera şu an sadece "Charge mode"da görünüyor (idVendor 1004:6300), tek arayüz HID — veri/video arayüzü yok, `/dev/video*` oluşmuyor. Webcam akışı için kameranın kendi WiFi AP modu (OSC API üzerinden) kullanılacak, USB sadece güç için.
- Var olan GitHub reposu bulundu ve bağlandı: https://github.com/akarafil/LG_360_cam_USB_Webcam (bu dizine `origin` olarak eklendi, `main` dalı checkout edildi).
  - Repoda hazır olanlar: `lglaf/` (root/flash aracı, opsiyonel/ileri seviye), `setup.sh`/`setup_network.sh` (kamera WiFi AP'sine bağlanma + NAT köprüsü), `camera_api.py` (OSC API ile UDP stream başlatma), `baslat.sh` (ffmpeg ile `/dev/video9` sanal webcam'e akış), `disable_sleep.py`.
  - Eksik: README/setup.sh'nin bahsettiği `main.py` (Flask web paneli + hareket algılama + kayıt) repoda yok; `requirements.txt`'teki flask/opencv/bleak buna ait ama karşılığı yok. Bu proje kapsamı dışında bırakıldı — kullanıcı projeyi "adım adım baştan" ele almak istiyor.
- Karar: Kamera daha önce root'lanmamış/backdoor kurulmamış kabul edilecek; root/lglaf adımı olmadan, cihazın standart WiFi AP modu (Güç + Deklanşör çift tık) üzerinden ilerlenecek. Rootlama isteğe bağlı, ileride ele alınabilir.
- Ortam kontrolü tamamlandı: `v4l2loopback` (v0.15.4) kurulu, `nmcli`, `ffmpeg`, `python3` (3.14.7) + `requests` (2.34.2) mevcut — ek kurulum gerekmiyor.
- Sıradaki adım: Kamerayı WiFi AP moduna almak (Güç + Deklanşör çift tık) ve bilgisayardan ağını bulup bağlanmak.
- GitHub push için bu makinede kimlik bilgisi yoktu (ne SSH anahtarı ne token). `~/.ssh/id_ed25519_github` oluşturuldu, `~/.ssh/config` ile github.com için bu anahtar tanımlandı, genel anahtar kullanıcı tarafından GitHub hesabına eklendi ve doğrulandı (`ssh -T git@github.com`). Repo remote'u SSH'a çevrildi (`git@github.com:akarafil/LG_360_cam_USB_Webcam.git`).
- `README.md` sıfırdan başlayan biri için adım adım kurulum kılavuzu olarak yeniden yazıldı: nasıl çalıştığı, gereksinimler, Adım 1-5 (bağımlılıklar → sanal webcam → kamerayı WiFi moduna alma → bağlanma → yayını başlatma), sorun giderme tablosu, rootlama bölümü "opsiyonel/doğrulanmadı" olarak işaretlendi, proje dosya yapısı açıklaması eklendi.
- **Düzeltme (kullanıcıdan):** Kameranın standart hotspot modu normalde Bluetooth ile tetikleniyor. Bu bilgisayarda Bluetooth donanımı yok (doğrulandı: `lsusb`/`lspci`/`rfkill`/`/sys/class/bluetooth` boş). Yine de kullanıcı Güç+Deklanşör kombinasyonuyla kamerayı denedi ve mavi ışık yandı (hotspot BT olmadan da açılabiliyor).
- Kullanıcı kalıcı/otomatik çözüm için rootlama yoluna karar verdi. Kamerayı manuel bir düğme kombinasyonuyla (kullanıcı biliyor, dokümante edilmedi) Download/LAF moduna soktu. USB'de cihaz `1004:633e "LM-X420xxx/G2/G3 Android Phone (MTP/download mode)"` olarak göründü.
- Ortam hazırlığı: Arch'ta sistem pip "externally-managed" olduğu için proje köküne `venv/` oluşturuldu, `pyusb`, `requests`, `cryptography` bu venv'e kuruldu. `lglaf/rules.d/42-usb-lglaf.rules` kullanıcı tarafından `/etc/udev/rules.d/`'e kopyalanıp `udevadm control --reload-rules && udevadm trigger` ile aktifleştirildi (idProduct 633e zaten kural setinde tanımlıydı).
- **Milestone — Root erişimi doğrulandı:** `venv/bin/python lglaf/lglaf.py --cr -c "id"` → `uid=0(root) gid=0(root)`. Düz `lglaf.py -c "id"` (cr olmadan) `LAF_ERROR_ACCESS_DENIED` veriyordu; `--cr` (challenge-response, KILO CENT/METR) bayrağı zorunlu.
- Sıradaki adım: Kullanıcıyla onaylanacak — `/system/bin/install-recovery.sh` içine kalıcı/otomatik WiFi-hotspot açan betiği enjekte etmek (README'deki "İleri Seviye" adımı), bu sistem partisyonuna yazan, geri alması nispeten zor bir işlem.
